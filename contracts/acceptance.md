# Acceptance Guide

本文档固定 MVP v1.0 当前阶段验收口径，供后端、前端、测试和交付使用。

## 1. 四阶段验收点

| 阶段 | 可验收产物 | 必须通过的确认点 | 锁定条件 |
|---|---|---|---|
| 阶段一：场景解构与风险定级 | `scenario_summary`、风险矩阵、HITL 明细 | 场景边界、风险等级、HITL、禁入规则 | 关键风险有证据，人工确认完成 |
| 阶段二：价值建模与目标 SLA | 价值 / SLA 结果草稿 | 参数来源、目标 SLA、敏感性提示 | 参数来源可追溯，autoResearch 建议已处理 |
| 阶段三：任务拆解与微型探针 | 探针结果草稿、Actual SLA 汇总 | 原子任务、样本台账、低分归因 | 样本与评分记录可追溯 |
| 阶段四：三维对齐与报告 | 阶段四结果、报告草稿、决策卡、证据目录、导出包 | 证据融合、最终建议、报告引用 | 报告引用完整，审批结束检查清单通过 |

## 2. 端到端验收步骤

1. 准备 1 个固定演示项目。
2. 准备 1 套固定输入材料，至少包含：
   - 1 份文本材料
   - 1 份图片或截图材料
3. 从前端入口或 API 入口创建项目。
4. 上传文本和图片材料。
5. 对文本材料执行解析，对图片材料执行视觉解析。
6. 跑通四阶段，每阶段至少生成：
   - 1 个草稿版本
   - 1 个锁定版本
7. 至少 1 个阶段触发 autoResearch 建议，并完成：
   - `accepted`
   - `accepted_with_edits`
   - `rejected`
   三者之一。
8. 检查每阶段锁定前的：
   - `version_logs`
   - `execution_logs`
   - `evidence_item_ids`
   - `confirmation_ids`
9. 生成最终报告、决策卡、证据目录和导出包。
10. 使用同一输入至少重跑 1 次，验证：
   - 核心结果可复现，或
   - 差异可解释，且 `version_logs.details.diff_summary` 有记录。

## 3. 必须通过的验收结果

- 四阶段结果均可追溯到输入材料或证据。
- 版本日志、执行日志、证据索引完整。
- 报告输出为以下三者之一：
  - `建议立项`
  - `建议暂缓（补充论证）`
  - `不建议立项`
- 锁定版本不可被覆盖。
- autoResearch 不能直接锁定结果，也不能绕过人工确认直接改最终结论。

## 4. 不通过条件

出现以下任一情况即判定不通过：

1. 阶段结果无法追溯到输入材料或证据。
2. 已锁定阶段版本被覆盖。
3. autoResearch 自动改写最终结论且没有人工确认记录。
4. 报告关键结论没有证据引用。
5. 重跑后产生差异，但没有差异摘要。
6. 文件只存在本地路径，MongoDB 中没有对应索引或证据关系。

## 5. 当前自动化覆盖

当前自动化已覆盖：

- API 成功路径与关键失败路径
- 响应结构契约一致性
- Agent / Skill 核心约束
- 一条固定后端 API 入口端到端验收流

当前自动化未覆盖：

- 浏览器级前端端到端验收脚本
- 真实外部视觉模型联调
- 交付期静态托管验收
