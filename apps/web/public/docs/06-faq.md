# 常见问题

## 草稿与发布的区别

- **草稿** — 修改后未发布的状态，保存在当前会话，不生效
- **发布** — 写入新的配置版本，之后所有 Run 都用这个版本

> 只有发布后，配置才真正生效。草稿丢失不会影响已发布版本。

## 提示词缺少必需变量

顶部红色提示会列出缺失的变量。补齐后才能发布。

检查要点：

- 变量名前后是双花括号 `{{project_goal}}`
- 区分大小写
- 阶段类模板才会校验，Skill 类模板不校验

## Skill 不在可选列表

每个 Skill 有一个 `stage_suffix`，决定它能用在哪些阶段。当某 Skill 不在当前阶段的可选列表时，说明它的 `stage_suffix` 与当前阶段不匹配。

排查方法：

1. 看后端 `skills/registry.py` 的定义
2. 确认 `stage_suffix` 是否为 `stage-{N}` 或 `unknown`
3. 如果是 `unknown`，可以适配任意阶段

## 工具或子代理列表为空

- **工具列表为空** — 该 Skill 没有定义 `allowed_tools`，或主 Skill 未选
- **子代理列表为空** — 该 Skill 没有定义 `allowed_subagents`，或主 Skill 未选

## 版本字段为什么是 mvp-v1

当前只有 `mvp-v1` 一个版本，保持默认即可。这个字段用于审计追溯：每次 Run 都会把当时的 Skill 版本号写入 StageResult。未来 Skill 升级后，这里会自动列出可选版本。

## 模型配置填了但不生效

排查要点：

- 「启用」开关是否打开
- 模型名称是否正确（传给 API 的 `model` 参数）
- Base URL 是否到 `/v1` 这一级
- 是否配置了「通用」角色，阶段 Skills 默认用它

## 如何回滚到旧版本

在「运行与留痕」分区底部查看版本历史，按版本号回滚。回滚后一并回滚提示词、Skills、模型配置与运行策略。
